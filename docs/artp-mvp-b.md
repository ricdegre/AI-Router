# ARTP/1 MVP B (experimental)

ARTP now has an explicit preview → create → resume flow. Preview remains read-only. `POST /api/artp/tasks` accepts the descriptor, optional staged image draft and attachment IDs, the **semantic and base-manifest hashes returned by preview**, an idempotency key, and optional routing preferences. Core recompiles every create request. If aliases, project registration, policy, validators, or attachments changed, it returns `ARTP_STALE_PREVIEW`; the user must preview and confirm again. Creation persists the task but does not run it. The ordinary task resume endpoint runs it through the existing orchestrator.

The VS Code panel exposes **Execute ARTP** only after a preview. Run Task with ARTP still previews rather than auto-executes. Editing the descriptor invalidates the visible execute action. Historical Compact and Expanded Views are available in task details as `artp_view`; they use the frozen task descriptor rather than current alias revisions.

ARTP task descriptors are v0.2, with original text/hash, canonical semantic/hash, effective policy hash, base Context Manifest/hash, project registration identity, alias revisions/hashes, validator binding hashes, image identity/hash, and acceptance criteria. Provider/profile/model/effort/channel are separate from the semantic hash. Traditional v0.1 descriptors remain readable; explicit v0.1→v0.2 migration makes a backup and does not reinterpret historical meaning. Resume/retry never recompiles ARTP or re-resolves aliases.

The common ContextBuilder plans mandatory task, policy, image references, and explicitly required source files, then renders for the selected candidate budget. Required source files are full text; if mandatory content does not fit, execution fails with `MANDATORY_CONTEXT_TOO_LARGE` rather than truncating it. Optional project inspection can be omitted. The per-attempt manifest records hashes, files, modes, omissions, budget, destination, images and validation IDs—never source contents or image bytes. It feeds the existing provider-neutral Execution Envelope and orchestrator, not a second ARTP engine.

`TEST` accepts registered validation IDs only. The host supplies trusted definitions; a descriptor cannot specify an arbitrary command. File targets must be inside task scope. Registered command validators run via the existing shell-free ValidationCommandRegistry with bounded timeout. Unknown IDs or changed definitions fail closed. `DONE` is model-facing acceptance text; task completion still depends on action postconditions and configured validation.

Metrics distinguish descriptor bytes/chars and `chars/4` **estimates** from actual provider input/output tokens when returned (including Ollama's prompt/eval counts). The attempt records selected context, hashes, and persistent alias count. These do not prove universal token savings. A controlled A/B must use the same baseline, provider/model/effort, validation target and attachments; restore baseline between traditional and ARTP attempts, and separately report user-input reduction, actual provider-input reduction (or unavailable), persistent reuse, correctness, validation, actions and execution time. Never infer provider tokens from descriptor length.

Limitations: ARTP's `F`/`REF` source selection is deterministic, not semantic retrieval; required files that exceed the candidate budget block rather than summarizing. Validator registration is host configuration, not a dashboard editor. No learning loop, context promotion, metered fallback, or public release is implied. The installed VSIX must be repackaged/reinstalled to receive this UI change.

The first controlled local A/B result is recorded in [the benchmark report](artp-mvp-b-benchmark-20260923.md).
