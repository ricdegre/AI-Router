## 2. Qué es AI Router

AI Router es una herramienta tuya, local, que reparte trabajo de programación entre varios modelos de IA sin perder el contexto del proyecto. La idea central es: **"el modelo puede cambiar, la memoria del proyecto no"**.

Cómo funciona:

1. **Le das una tarea** desde VS Code, el panel web o la línea de comandos. Por ejemplo, "cambia el color del encabezado" o "arregla el bug del botón guardar".
2. **AI Router la analiza.** Decide qué tipo de tarea es (edición, bug, arquitectura…), qué tan difícil es, si escribe archivos y si necesita ver imágenes.
3. **Elige un modelo.** Las tareas ligeras van a un modelo local gratis (Ollama en tu RTX 3060) o a uno gratuito de OpenRouter. Los bugs y funciones van a una suscripción fuerte (Claude, ChatGPT). La arquitectura va al modelo más potente. No usa nada de pago por consumo salvo que lo autorices.
4. **El modelo propone cambios, pero no los hace él.** AI Router revisa cada cambio y comprueba que el archivo no cambió mientras tanto. Guarda copia de seguridad, aplica el cambio y valida el resultado.
5. **Si un modelo falla**, la tarea debería pasar a otro modelo con el mismo estado. Hoy esto solo funciona para algunos tipos de fallo (hallazgo #2).
6. **Deja todo anotado:** memoria del proyecto, traspaso (*handoff*), auditoría y diario de recuperación. Así otro agente puede continuar.

Versión: `0.12.0-pre.0`. Es una versión previa, no lista para producción.

## 3. Arquitectura (cómo está armado)

### 3.1 Dos carpetas separadas

- **El repositorio** (`<workspace>/AI-Router`) contiene solo código y documentación. Es público y sin secretos.
- **La carpeta de datos privada** (`AI-Router-Data`, indicada por `AI_ROUTER_DATA` o por `dataRoot` en `config/local.json`). Contiene perfiles, claves cifradas, memoria de proyectos, tareas, auditoría, copias de seguridad y logs. Nunca va a Git.

### 3.2 Proveedores (los "motores" de IA)

Se registran en `core/runtime-services.js:60-66`.

| Proveedor | Tipo | Cómo se conecta | Archivo |
|---|---|---|---|
| Ollama | Local, gratis | HTTP a `127.0.0.1:11434`, sin clave | `providers/ollama/ollama-provider.js` |
| OpenRouter | Nube, modelos gratis y de pago | Clave API cifrada con DPAPI | `providers/openrouter/openrouter-provider.js` |
| Gemini API | Nube, de pago | Clave API. **Apagado** hasta que lo autorices. | `providers/gemini/gemini-provider.js` |
| ChatGPT / Codex | Suscripción | Programa oficial "Codex App Server", con inicio de sesión de ChatGPT en el navegador. Cada perfil usa su propia carpeta. | `providers/openai/` |
| Claude Code | Suscripción | Programa oficial `claude` ya autenticado, con herramientas desactivadas | `providers/anthropic/claude-code-provider.js` |
| Google Antigravity | Suscripción | Programa oficial `agy` | `providers/google/antigravity-provider.js` |

Un **perfil** es una combinación concreta de proveedor, cuenta y modelo, por ejemplo "gemma4 = Ollama + gemma4:26b". Los perfiles se crean desde el panel y se guardan en `AI-Router-Data/accounts/profiles.json`.

### 3.3 Ruteo y Triage

- `routing/task-analysis.js` clasifica la tarea.
- `routing/policy.js` aplica reglas fijas: salud, capacidades, coste, límites. Ordena los candidatos y explica por qué acepta o descarta cada uno.
  - Regla importante (`routing/policy.js:14`): los modelos locales de **menos de 20.000 millones de parámetros** no se usan para bugs o funciones de dificultad media.
- **Triage** (`decision-engines/triage/`) es un clasificador opcional con un modelo local (`qwen3.5:9b`). En tu configuración está en modo **sombra**: da su opinión y se registra, pero no cambia la ruta.

### 3.4 ARTP

ARTP es un formato estricto para escribir tareas. Empieza con `ARTP/1` y sigue con campos como `P:`, `DO:`, `F:`…
- **ARTP runtime** (`artp/`) funciona en tres pasos: vista previa, crear y reanudar, con alias privados versionados.
- **ARTP portable** (`AI-CONTEXT/PROTOCOL.md`) es solo una convención de texto para agentes. No registra nada.

### 3.5 API de control y panel web

- Servidor: `interfaces/control/control-server.js`.
  - Solo escucha en `127.0.0.1`; cualquier otra dirección se rechaza en el código (línea 51).
  - Puerto 43127; si está ocupado, usa el siguiente libre.
- Protecciones comprobadas en vivo durante esta auditoría:
  - Rechaza peticiones con un `Host` distinto (`UNSAFE_CONTROL_HOST`).
  - Rechaza peticiones que vienen de otra web (`UNSAFE_CONTROL_ORIGIN`).
  - Para cambiar algo exige un código secreto de sesión (*nonce*).
- Panel: `interfaces/dashboard/`. Es HTML y JS propio, sin Internet. Páginas: Overview, Profiles, Routing, Tasks, Audit, Settings y VS Code.

### 3.6 Extensión de VS Code

### 4.3 Defectos encontrados en el código

Las líneas son del código antes de los arreglos de esta rama.

**Alta**
- **#2 Fallback**
  - Dónde: `core/task-execution-descriptor.js:170`. La lista por defecto de fallos que permiten pasar a otro modelo solo tiene `timeout`, `execution_failure`, `malformed_output`, `validation_failure` y `action_rejected`. `core/resilient-orchestrator.js:427` solo escala si el fallo está en esa lista.
